# ESP32-S3 Touch Map

Offline raster map on a Waveshare ESP32-S3-Touch-LCD-4.3. Tiles come from a microSD card; position, route and
turn instructions come from an iPhone over Bluetooth LE. Built from *SRS & System Design Guide, Draft 0.9*.

```
main -> ui -> kernel -> hw_hal        three layers, one direction (docs/ARCHITECTURE.md)
```

## Open in VS Code

1. Install the recommended extensions (`.vscode/extensions.json`): **Espressif ESP-IDF**, C/C++, Python.
2. Install **ESP-IDF 5.4** with the extension's setup wizard, then `ESP-IDF: Set Espressif Device Target` -> `esp32s3`.
3. `Terminal > Run Task`:

| Task | What it does |
|---|---|
| IDF: build | `idf.py build` (fetches the `esp_jpeg` managed component on first run) |
| IDF: flash + monitor | asks for the serial port, flashes and opens the monitor |
| Host: unit tests | portable code on your PC, no board needed |
| Check layering | fails if a layer includes something it should not |
| Make demo tile pack | writes synthetic packs to `sdcard/maps` for first bring-up |
| Regenerate font | rebuilds the Inter font tables (needs Pillow and the Inter .otf files) |

Debugging: `Run > ESP32-S3 GDB (built-in USB-JTAG)` (USB-C, GPIO 19/20).

## Without the board

```
make -C test/host run          # 67 checks: BLE protocol, Mercator math, .tpk format
make -C test/host packs        # tilepack.py writes packs, the firmware's C parser reads them
python3 tools/check_layers.py  # layering rules
make -C sim run && python3 sim/to_png.py    # render the real UI to sim/out/*.png
```

## First bring-up on hardware

1. `python3 tools/tilepack.py demo --out sdcard/maps`, copy `sdcard/maps/` to a FAT32 microSD card.
2. Build and flash. Expect the map screen with the demo tiles, grey blocks while they load, and
   "Waiting for phone (BLE: ESP32-Maps)" at the top.
3. Work through the test plan T-01..T-12 in the SRS. Real map data: `tilepack.py estimate / fetch / pack`
   (use a tile provider whose licence allows offline use; the tool refuses the OpenStreetMap servers).
4. The phone page (Bluefy) is not part of this project yet. `docs/BLE_PROTOCOL.md` is its contract.

## What is verified, honestly

Verified here, on a PC:

* Portable code (`k_proto`, `k_geo`, `k_tpk`) builds with `-Wall -Wextra -Wconversion` and passes 67 checks
  under AddressSanitizer and UBSan. Tile coordinates were checked against an independent implementation of the
  slippy-map formula.
* A `.tpk` written by `tools/tilepack.py` is parsed and fully validated by the firmware's own C code.
* The whole UI layer compiles warning-free and renders (sim): navigation, all 14 maneuver arrows, off-route,
  stale position, miles, grey tiles, settings, Bluetooth, Storage, About, factory-reset dialog, SD errors.
  Taps drive the screens through the real touch handlers.
* Layering rules hold.

**Not verified: anything that needs ESP-IDF or the board.** `hw_hal` and most of `kernel` (FreeRTOS tasks,
NimBLE, FatFs, NVS, drivers) have never been compiled or run. Expect to fix compile errors on first build. Check first:

| Item | Where |
|---|---|
| `esp_jpeg` call and field names (SRS OI-3) | `hw_hal/src/hal_jpeg.c` |
| EXIO3 really is the LCD reset (OI-4) | `hw_hal/include/board_config.h` |
| NimBLE API usage and `CONFIG_BT_NIMBLE_*` option names | `kernel/src/ble/k_ble.c`, `sdkconfig.defaults` |
| FatFs drive number via `ff_diskio_get_pdrv_card` | `hw_hal/src/hal_sd.c`, `hal_file.c` |
| RGB LCD timings, PCLK polarity, bounce buffer vs flicker | `hw_hal/src/hal_lcd.c` |
| sdkconfig symbol names for PSRAM / IRAM-safe LCD | `sdkconfig.defaults` (run `idf.py menuconfig` if one is rejected) |
| GT911 release detection (UP debounce of 3 polls) | `kernel/src/display/k_input.c` |

Planned and not built: passkey pairing and bonded phones (BLE-06), device-name editor (BLE-08), night palette
colours (NAV-07), all WiFi features (WIFI-01..08), the phone web page. See `docs/TRACEABILITY.md`.

## Fonts

Text uses **Inter** (SIL Open Font License 1.1): Medium at 16 px for body text and SemiBold at 30 px for titles,
anti-aliased and proportional, which is the closest open match to the iPhone's San Francisco (Apple's font is
licensed for Apple platforms only). Tables are generated by `tools/gen_font.py` into `components/ui/src/gfx/font_ui.c`
(about 45 KB of flash). Change `FACES` in the script to try another weight or size.
